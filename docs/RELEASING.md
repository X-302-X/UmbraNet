# Выпуск новой версии

## Номер версии

Текущая версия живёт в одном месте — [`umbranet/__init__.py`](../umbranet/__init__.py)
(строка `__version__`). Формат: **три числа + буква стадии**, например `26.0.1b`.

Обозначения стадий: `a` — альфа, `b` — бета, `r` — стабильный релиз.

| Буква | Стадия | Пример тега GitHub |
|---|---|---|
| `a` | альфа | `v26.0.1a` |
| `b` | бета | `v26.0.1b` |
| `r` | стабильный релиз | `v26.0.1r` |

**Как версии сравниваются:** сначала три числа, потом буква (`a` < `b` < `r`).
Поэтому `26.0.2a` новее, чем `26.0.1r`. Внутри программы сравнением занимается
`core/app_version.py` — руками версии сравнивать не нужно.

**Никогда не перезатирай опубликованный тег.** Новая сборка — это новый номер
(`26.0.1b` → `26.0.2b`): одинаковые версии обновлением не считаются, и люди
просто не увидят новую сборку.

## Как программа узнаёт о новой версии

- UmbraNet проверяет страницу **Releases** репозитория
  [X-302-X/UmbraNet](https://github.com/X-302-X/UmbraNet/releases): при запуске
  и дальше раз в 24 часа (после сетевой ошибки повтор через час).
- Стабильный канал (по умолчанию) видит **только релизы `r`**. Альфы и беты
  видны лишь тем, кто сам включил тестовый канал во вкладке «О программе».
- **Git-тега недостаточно** — проверка обновлений видит только GitHub Release.
  Опубликовал тег → создай к нему Release.
- Черновики (draft) и версии в неправильном формате пропускаются.
- Программа ничего не скачивает и не устанавливает сама — только показывает
  уведомление и ссылку на страницу релиза.

## Порядок выпуска (чек-лист)

1. **CI зелёный** на релизном коммите (Windows + Linux × Python 3.10–3.15).
2. **Чистая установка на Windows:** `install.bat` → `pip check` → программа запускается.
3. **Ручная приёмка:** DNS стартует и останавливается, системный DNS возвращается
   при выходе; движок запускается; подписки обновляются; «О программе» не зависает
   при проверке обновлений.
4. **Подними версию** в `umbranet/__init__.py` **и в README** (строка под заголовком).
5. **Тег и релиз:** тег `v26.0.1b` → GitHub Release на этот тег. Для `a` и `b`
   обязательно поставь галку **Prerelease**.
6. **Опиши релиз** по-человечески: что нового, что исправлено.

## Обновление зависимостей

- Прямые зависимости (`requirements.txt`) и транзитивные (`constraints.txt`)
  обновляй **вместе**.
- После изменения: чистое окружение → установка обоих файлов → `python -m pip check`
  → полный прогон тестов (CI-матрица: Windows/Linux × Python 3.10–3.15).
- Не копируй в `constraints.txt` весь вывод `pip freeze` — там будет лишее.
- `PySide6` закреплён на 6.12.0: это первая проверенная в UmbraNet версия с wheel для Python 3.15.
